## Alternative frontend recommendation

**SystemVerilog:** **(b) `yosys-slang` when present, with `read_verilog -sv` as fallback.** Built-in `-sv` already emits `.sv` `src` locations for `logic`, `always_*`, enums, packed structs/unions, interfaces/modports, and `pkg::W`, but breaks on core student idioms (`import pkg::*`, `return`). `yosys-slang` (ISC) covers those, keeps `src` `file:line`, and ships in OSS CAD Suite; `synlig` is absent there and slowing.

**VHDL:** **(e) `ghdl-yosys-plugin` (`yosys -m ghdl`)**, paired with **(f) deferring VHDL until OSS CAD Suite is present locally.** Avoid **(d)**'s `--out=verilog` comment-to-`src` post-processor: `ghdl-yosys-plugin` keeps `file.vhdl:line` `src` attributes natively and ships with `slang` in OSS CAD Suite, while Homebrew `ghdl` is disabled on macOS (`fails_gatekeeper_check`) and missing on the build server.

**Install:** **(g) OSS CAD Suite as the single supported toolchain on macOS and Linux**, replacing Homebrew `yosys`. Plugins are ABI-coupled to Yosys and missing from Homebrew, Homebrew `ghdl` fails macOS Gatekeeper, and CI already uses OSS CAD Suite (`2026-10-22`). Keep Homebrew `yosys` only as a fallback for existing setups.

**First slice to ship with tools already installed:**
- Accept `.sv` in `ecp5.toml`, probing for `slang` (`yosys -m slang`) and falling back to `read_verilog -sv` -> `synth_ecp5`.
- Reuse existing `src` die cross-probing on `.sv`, document the `-sv` subset (`import pkg::*` and `return` unsupported without `slang`), and fail `.vhd`/`.vhdl` builds cleanly unless `ghdl` plugin support is detected, pointing users to OSS CAD Suite.

**Biggest risk:** OSS CAD Suite plugin behavior is unverified locally—specifically whether `slang`/`ghdl` `src` strings (paths, ranges, generate blocks) parse cleanly in the cross-prober through `nextpnr-ecp5`, alongside macOS quarantine or `PATH` shadowing by Homebrew `yosys` for students.

**Confidence:** `0.85`

**Evidence that would change the verdict:**
- Local OSS CAD Suite `2026-10-22` tests showing `yosys -m slang` or `-m ghdl` drops/mangles `src` attributes in `nextpnr-ecp5` JSON (would push VHDL to **(d)** or require `src` normalization).
- macOS Gatekeeper blocking OSS CAD Suite's `ghdl` or `.so` plugins too (would force **(a)** + **(f)** on macOS).
- Any distribution model where `ghdl-yosys-plugin`'s GPL-3.0 applies beyond separate-process CLI invocation (would favor **(d)** or **(f)**).
- Curriculum/usage data showing students never need `import pkg::*` or `return` in SV (would make **(a)** sufficient).
